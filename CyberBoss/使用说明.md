# CyberBoss 使用说明

一个装在你自己电脑上的微信 AI 助手。加它微信，直接说话就行。

---

## 〇、开始

**双击桌面上的 `CyberBoss`。**

完事。它会自己更新代码、装好一切、然后问你三个问题——**一路回车就行**。

最后它会显示一个二维码，用**要当机器人的那个微信**扫一下。

> 用哪个微信扫，以后就是哪个微信在跟人说话。建议用小号。

以后想启动，还是双击桌面上那个 `CyberBoss`。

---

## 二、认领它

用**你自己的微信**，给刚才扫码的那个号发一句话，随便什么都行：

> 你好

它会回你：

> 认出你了，你是这里的主人 ✓

**第一个发消息的人就是主人。** 所以装好之后请你自己先发一句，别让别人抢先。

---

## 三、日常怎么用

全都在微信里，直接发这几个词：

| 你发 | 它做什么 | 谁能用 |
|---|---|---|
| 随便说话 | 正常聊天 | 所有人 |
| **记一下 今天跑了五公里** | 记进你的时间线 | 所有人 |
| **提醒我 明天9点 交房租** | 定一个提醒 | 所有人 |
| **我的记忆** | 看最近的记录 | 所有人 |
| **最近7天** | 看这周都干了什么 | 所有人 |
| **可以问我** / **别再问我** | 开关主动问候 | 所有人 |
| **帮助** | 告诉你能做什么 | 所有人 |
| **设置** | 给你一个网页链接，去填自己的 AI 密钥 | 所有人 |
| **邀请** | 给你一串邀请码，转发给朋友 | 只有主人 |
| **状态** | 说说现在运行得怎么样 | 只有主人 |

> 「记一下」「提醒我」这些是**确定性**执行的 —— 由代码直接写进数据库，不经过 AI。
> 你说记，就一定记下了；也不花任何 AI 额度。
> 时间看不懂的时候它会照实说看不懂，而不是猜一个时刻然后在错的时间叫你。

---

## 四、让朋友也能用

1. 你发「**邀请**」
2. 它回你一串码，比如 `a1b2c3d4e5f6`
3. 把这串码转发给朋友
4. 朋友加了这个微信之后，把码发过来
5. 它让朋友确认一下隐私说明，朋友回「**同意并开始**」
6. 朋友就能用了

**一串码只能用一次，7 天过期。** 想再加人就再发一次「邀请」。

朋友的聊天记录、资料、AI 密钥，跟你的完全分开，互相看不到。

---

## 五、关于 AI 密钥

这个软件不替你出钱调用 AI。每个人用自己的密钥。

发「**设置**」→ 打开链接 → 填自己在 OpenAI / DeepSeek / Google / Anthropic 申请的密钥 → 就能聊天了。

**前提**：设置页面需要一个域名。装的时候第 ② 步填上就行，只填域名本身（像 `boss.example.com`），不用带 `https://`。

填了之后它会顺手把 Cloudflare 隧道的配置写好，并把四条命令打给你，照着敲完就通了。忘了命令随时敲：

```
cyberboss tunnel
```

> 为什么用隧道不直接开端口：隧道是从你这台机器**主动向外**连出去的，所以路由器和防火墙上一个入站端口都不用开，设置页面也只监听 `127.0.0.1`。外面扫不到它。

跳过这一步也能装完 —— 只是那个网页暂时打不开，聊天不受影响。

密钥存在你自己电脑上，用一把只有你能读的钥匙加密，转成密文之后才落盘。软件不会把它显示出来，也不会写进日志。

---

## 六、出问题了

任何时候敲：

```
cyberboss doctor
```

它会告诉你现在什么正常、什么没配好。

如果启动时报错，屏幕上会直接写「怎么办」，照着做就行。常见的两个：

- **还没有登录微信** → 敲 `cyberboss login`，重新扫码
- **工作目录的配置还没准备好** → 敲 `cyberboss setup`

---

## 七、你的数据在哪

全在你自己电脑上，`~/.cyberboss` 这个文件夹里。没有云端账号，没有第三方服务器。

任何用户都可以随时发：

- **导出我的数据** —— 把自己的东西拿走
- **删除我的数据** —— 把自己的东西删掉

---

## 八、备份

数据全在你自己电脑上，所以备份也归你管。敲：

```
cyberboss backup
```

它会做一份一致的数据库快照 → 打开检查确实能用 → 加密 → **同时**写到 Cloudflare R2 和 OCI 两个地方。

**两份都写成功才算数。** 有一边失败就整次失败，不会给你一张"看起来备份好了"的收据 —— 那种收据会在你真正需要它的那天才露馅。

配置（写进 `~/.cyberboss/.env`）：

```
CB_R2_ACCOUNT_ID=你的账号id
CB_R2_BUCKET=桶名
CB_R2_ACCESS_KEY_ID=...
CB_R2_SECRET_ACCESS_KEY=...
CB_OCI_PAR_URL=https://objectstorage.../o/
```

没配就直接告诉你缺哪个，不会偷偷只写一份。

**现在的实测状态（2026-07-28，用你 `_protected/` 里的真实凭据跑过）：**

| | 结果 |
|---|---|
| OCI 对象存储 | ✅ **通了** —— 真的写进去了，返回了版本标识 |
| Cloudflare R2 | ❌ 403 拒绝 —— 不是签名问题（R2 回的是 `AccessDenied` 不是 `SignatureDoesNotMatch`），是**这把密钥没有写 `cyberboss-cold` 桶的权限** |

`_protected/` 里唯一的 R2 S3 密钥是 `weread_port_r2_v0019.env`，它写不了 `cyberboss-cold`（`cyberboss-cold` 这个桶 2026-07-27 就建好了，但没有配套密钥留档）。

**你要做的（3 分钟）：** Cloudflare 控制台 → R2 → 「Manage R2 API Tokens」→ 建一个 token，权限选 **Object Read & Write**，桶选 **cyberboss-cold** → 把给你的 Access Key ID 和 Secret 填进 `~/.cyberboss/.env` 的 `CB_R2_ACCESS_KEY_ID` / `CB_R2_SECRET_ACCESS_KEY`，然后再跑一次 `cyberboss backup`。

> 我没有替你去建这个 token，也没有建桶 —— 那是改你 Cloudflare 账号的设置，该由你自己点。

云上那份是密文，用一把只在你这台机器上的密钥加密。桶被人读走也解不开。

---

## 九、还没做好的

老实说两件：

1. **一键部署到服务器** —— 现在只能在你自己电脑上跑。想放到 OVH 上要自己配 systemd。
2. **R2 还差一把有写权限的密钥** —— 见上面「备份」一节，3 分钟能配好。OCI 那半边已经用你的真实凭据实测通过了。
3. **AI 密钥没用真的调过** —— 四家 provider 的代码路径全部端到端测过（包括密钥真的出现在了发往 `api.openai.com` 的请求头里），但我没有替你花钱真调一次付费 API。你第一次在设置页面填完密钥，发一句话就知道通没通。

其余的都通了。
