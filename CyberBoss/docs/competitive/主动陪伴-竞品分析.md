# 竞品分析：CyberBoss、知你，以及「真正的主动陪伴」

对标对象两个，都在微信里，都声称会主动找你：

| | CyberBoss | 知你（人机恋.com） |
|---|---|---|
| 出处 | `WenXiaoWendy/cyberboss`，本项目的原型（见 `UPSTREAM_PROVENANCE.md`） | 独立商业产品 |
| 形态 | 自托管，开源 | 托管 SaaS，扫码即用 |
| 面向 | ADHD／需要外部问责的人 | 想要一个记得自己的 AI 朋友 |
| 一句话 | 「你尽管继续逃进多巴胺。下一个时间戳我照样逮到你。」 | 「越聊越懂你，不用反复解释背景」 |
| 收费 | 无 | 免费版 + 至臻版 |

---

## 一、CyberBoss：会做事，但不懂你

**它真正做对的事**

1. **时间是一等公民。** 每条消息都带时间戳，模型因此知道「你说这句话是凌晨三点」。绝大多数聊天机器人没有这个概念。
2. **主动不需要你先开口。** 随机唤醒——不是定时任务，是让 agent 自己决定什么时候插话。这是它区别于所有「你问我答」产品的根本。
3. **有手。** 后面接的是 Codex / Claude Code，所以它能真的改文件、跑命令，不只是说话。
4. **数据在自己机器上。** 日记写本地文件，不依赖云。

**它的结构性缺陷**

1. **只有一个人能用。** 整个设计里没有「第二个用户」的位置——没有身份、没有隔离、没有额度。想给朋友用，只能再装一套。
2. **门槛是开发者级的。** `npm run shared:start`、`/bind`、终端诊断。README 面向的是会读代码的人。
3. **主动是随机的，不是有依据的。** 随机唤醒的代价是：它找你的时候，并不知道该说什么，只能问「在干嘛」。次数一多就是骚扰。
4. **框架是对抗性的。** 「boss」「catch you」——它把自己放在你的对立面。短期有效（愧疚驱动），长期会被静音。
5. **没有记忆模型。** 有时间线、有日记，但那是**记录**，不是**理解**。它不会因为「你连着三个周三都在拖同一件事」而改变行为。

---

## 二、知你：懂你，但不做事

**它真正做对的事**

1. **零门槛。** 扫码，就是微信里多一个好友。这是普通人唯一能接受的安装方式。
2. **把记忆当成卖点讲。** 「不用反复解释背景」精准命中了所有 AI 产品的最大痛点。
3. **多模态。** 图片、语音进，图片出——在微信里这是刚需，不是加分项。
4. **人格可定制 + 多档模型。** 给了用户「这是我的」那种拥有感，同时把成本分层变成了功能分层。
5. **情绪价值定位清晰。** 域名叫「人机恋」，毫不含糊。

**它的结构性缺陷**

1. **你的数据在别人服务器上。** 长期记忆越丰富，这一条越致命。没有导出，没有可验证的删除。
2. **它只会说话。** 没有工具、没有执行。你说「帮我把这个整理成文档」，它只能给你一段文字。
3. **主动是产品化的，不是有依据的。** 「主动开口」是一个可以关掉的开关，内容是通用的想念句式，不是从你自己的记录里长出来的。
4. **人格是一套皮。** 你设定它的性格，而不是它建立对你的模型。方向反了。
5. **一个账号一个人格，多人共用一台没有隔离。** 商业上没必要解决，但一旦要给家人／团队用就没了。

---

## 三、这个项目已经站在哪儿

同时具备两边的核心能力，这是它们各自都没有的：

| 能力 | CyberBoss | 知你 | 本项目 |
|---|---|---|---|
| 微信原生、扫码可用 | 部分 | ✅ | ✅ |
| 时间感知 / 时间线 | ✅ | 部分 | ✅ |
| 长期记忆与画像 | ✗ | ✅ | ✅ |
| 会用工具、能真的做事 | ✅（仅主人） | ✗ | ✅（主人） |
| 多用户，彼此加密隔离 | ✗ | ✗ | ✅ |
| 各人用各人的额度（BYOK） | ✗ | ✗ | ✅ |
| 邀请制、可暂停、可彻底删除 | ✗ | ✗ | ✅ |
| 导出 + 双副本备份 + 恢复验证 | ✗ | ✗ | ✅ |
| 自己的域名、自己的服务器 | ✅ | ✗ | ✅ |

**已经领先的一句话：** 别人要么把你的数据放在自己手里（知你），要么根本没有「第二个用户」这个概念（CyberBoss）。这里两件事都解决了。

**但还没有领先的地方：** 主动性。目前的主动只有「提醒我」和 check-in——本质上还是定时器，和 CyberBoss 的随机唤醒是同一个层次。

## 四、「真正的主动陪伴」——超越点在这里

两个竞品的主动都建立在**时间**上：一个随机，一个偶尔。真正的主动应该建立在**证据**上。

### 四条设计原则

**1. 有依据才开口（evidence-gated proactivity）**

每一次主动都必须能追溯到用户自己记录里的一个具体触发点，而不是一个到期的定时器。

- 「你上周三说要交的那份东西，到今天一次都没提过。」
- 「这是你连着第三个晚上提到同一件事了。」
- 「你说想学的那个，已经二十天没动静。」

技术上这不是新东西：`activity_daily` 的聚合、`profile_facts` 的事实库、时间线的事件流已经全在库里。缺的是**从这些数据里生成触发条件**的那一层。

**2. 说得出为什么（explainable initiative）**

每条主动消息都能回答「你怎么知道的」，并且用户可以当场纠正：「这件事我已经做完了」→ 事实库更新，不再提。

被纠正过的主动比没被纠正过的更值得信任。两个竞品都做不到这一点，因为它们的主动本来就没有依据可以解释。

**3. 会闭嘴（the mute is the feature）**

主动性没有静音就是骚扰。「别再问我」这条口令已经存在，但还要更细：
- 按话题静音（这件事别再提），而不只是全局静音
- 主动频率随「被无视的次数」自动下降
- 连续 N 次主动没有得到回应 → 自动降到最低频率，并且**告诉用户它这么做了**

**4. 主动之后能接着做事（initiative with hands）**

这是 CyberBoss 有一半、知你完全没有的：主动提起之后，能顺手把事做了。

- 「那份东西我先按上次的格式起了个草稿，要看看吗？」
- 「你说的那个时间我记下来了，明早再提醒你一次。」

对主人，后面是完整的开发助手运行时；对普通用户，是在他自己的额度上做**受限**的事（写记录、建提醒、整理资料），不碰系统。

### 与两个竞品的最终对位

| 维度 | CyberBoss | 知你 | 本项目的目标 |
|---|---|---|---|
| 主动的依据 | 随机 | 定时/通用 | **用户自己的记录** |
| 主动能否解释 | 否 | 否 | **能，且可纠正** |
| 主动能否关掉 | 全局 | 全局开关 | **按话题 + 自动降频** |
| 主动之后能做事 | 能（仅主人） | 不能 | **能，按角色限权** |
| 情感基调 | 对抗（逮住你） | 依恋（想你了） | **在意（有依据地惦记你）** |

「逮住你」会被静音，「想你了」会被腻烦。**有依据的在意**是唯一能长期留下来的那一种。

## 五、落地顺序（都建立在已有模块上，不新增运行时）

1. **触发规则层**：从 `activity_daily` + `profile_facts` + 时间线生成候选触发，纯确定性，可测。
2. **理由字段**：每条主动消息带上可解释的来源，用户回「已经做完了 / 别再提」直接改事实库。
3. **分话题静音 + 自动降频**：静音本身也是可解释的，降频要主动告知。
4. **主动后的执行**：普通用户限定在写记录、建提醒、整理资料；主人不变。

前三步不需要任何新的外部依赖，第四步复用现有的能力闸门（`OWNER_ONLY_CAPABILITIES` / `USER_CAPABILITIES`）。
