# CB-000 Codex App Server Compatibility

## Accepted baseline

- Exact and minimum verified CLI: `codex-cli 0.146.0-alpha.3.1`
- Older versions accepted: **no**
- Verification: 347 experimental JSON Schema files generated by the exact CLI,
  required method inventory, parameter inspection and adapter unit tests
- Live authenticated turn: **not executed in CB-000**

`minimum verified` means the lowest version this project currently accepts based
on evidence; it does not claim that older versions were tested or incompatible.

## Official constraints

The fresh Codex manual identifies App Server as the rich-client interface and
documents:

- bidirectional JSON-RPC 2.0 with the `jsonrpc` header omitted on the wire;
- stdio JSONL as the default transport;
- WebSocket as experimental/unsupported and suitable only for localhost or
  SSH-forwarded local use;
- non-local WebSocket requires authentication and TLS;
- `initialize` followed by `initialized`, then `thread/start` and `turn/start`;
- browser ChatGPT login, device code, API key or trusted access-token login are
  owned by the Codex CLI; cached credentials must never enter this repository.

Sources:

- <https://learn.chatgpt.com/docs/app-server.md>
- <https://learn.chatgpt.com/docs/auth.md>
- Fresh manual SHA-256:
  `9aa974cc5289fa8e54ddb3b62c0a09979ba7764dcb094c10499462573d73617e`

The installed CLI help additionally reports `stdio://` default, `unix://`, local
`ws://IP:PORT`, and WebSocket auth modes `capability-token` and
`signed-bearer-token`.

## Project transport/auth policy

- Production/default listener remains `ws://127.0.0.1:<port>` or stdio; never
  bind the Runtime publicly.
- `app/scripts/shared-common.js` constructs `ws://127.0.0.1:${port}`.
- App code never reads, copies or serializes Codex credentials. Authentication
  is a host activation prerequisite performed with `codex login` or
  `codex login --device-auth`.
- `codex login status` was read-only and reported a local ChatGPT login; this is
  not production activation evidence and no credential value was read.

## Method compatibility

Generated schema proves all used methods exist:

- client requests: `initialize`, `thread/start`, `thread/resume`,
  `thread/compact/start`, `thread/list`, `turn/start`, `turn/interrupt`,
  `model/list`;
- client notification: `initialized`;
- server requests: command/file approval and MCP elicitation.

Machine evidence and schema hashes are in `codex-protocol-methods.json`.

Two historical wire mismatches were corrected:

1. removed `thread/start` with an `input` field; a turn now requires a real
   thread ID;
2. removed the undefined wire field `accessMode`; the supported
   `approvalPolicy`/`sandboxPolicy` fields preserve the intended safety mode.
