# CB9-530 Private-Database 同步、R2 对象与 R2/OCI 冷备

**AC-022 / AC-027 / AC-028：NOT_RUN**（FR-022 / FR-027 / FR-028）

## 为什么是 NOT_RUN 而不是 PASS

任务包把这个节点标成 `environment_bound: true`，三条验收的 oracle 全都要**真实对象**：

- **AC-022**：「上传文件后 R2 对象校验 hash；OVH 缓存超过保留期清理；
  Private-Database 仅存对象引用。」
- **AC-027**：「同一事实重复同步不产生新记录或空提交；
  完成态在 5 分钟目标内可从 Private-Database 读回并校验。」
- **AC-028**：「R2 与 OCI 各有可验证对象；
  第一份不可读时第二份可在隔离目录恢复并核对关系。」

这三条没有一条能靠本地跑出来。**「读回来校验」的前提是先真的写进去过**，
而写进去要的是这台机器上没有的东西。

## 实测的缺失（不是推断）

| 探针 | 结果 |

| `CLOUDFLARE_API_TOKEN` | 未设置 |
| `OCI_CLI_CONFIG_FILE` | 未设置 |
| `GITHUB_TOKEN`（Private-Database 推送） | 未设置 |

## 明确不做的三件事

- **不等**。凭据不会因为等待而出现。
- **不绕过**。没有「先用本地目录假装是 R2」这种替代——
  一个能在本地跑通的备份链路，证明的是本地目录能写，不是 R2 能写。
- **不伪造成已验证**。仓库里已有 `backup/`、`canonical/`、`objects` 那几个模块，
  它们的单元测试是绿的。**那些绿灯不是 AC-022/027/028 的证据**：
  它们证明的是模块在被正确调用时行为正确，而这三条要证明的是
  「真的写进去了、真的读得回来、第一份坏了第二份真的能恢复」。
  拿前者充当后者，正是这套验收明令禁止的伪造回执。

## 凭据到位后要跑的顺序

1. 上传一个文件 → 校验 R2 对象的 hash → 确认 Private-Database 里只有对象引用，
   没有字节
2. 同一条事实同步两次 → 确认第二次不产生新记录、不产生空提交
3. 完成态写入后 5 分钟内从 Private-Database 读回并校验
4. 把 R2 那份设为不可读 → 从 OCI 那份在隔离目录恢复 → 核对两份的关系
5. 逐条把真实回执写进 `docs/evidence/CB9-530/`
