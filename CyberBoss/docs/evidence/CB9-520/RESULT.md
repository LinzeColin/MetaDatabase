# CB9-520 Timeline/Status 隐私投影与字段白名单

**AC-020 / AC-026 / AC-033 / AC-043 PASS**（FR-020 / FR-026 / NFR-003）

## 缺口不是「没有过滤器」

`session-event` 里的 `assertPublicPayload` 早就有了，判得也对：
键黑名单 + 微信 ID / 密钥 / 绝对路径的值形状，CB9-400 时逐条钉过。

缺口是**真实链路上没人调它**——它只在 Timeline 自己那份投影里跑。
于是隐私保证的形状是「我们有一个很好的过滤器」加上
「碰巧现在没人往公开面塞脏东西」，而后半句是行为保证：
下一个人加一条路由就没了，而且没有任何症状。

CB9-020 那次扫描扫的是 7 个模板文件的**静态文本**，`violations: []`。
模板是干净的，但模板里写的是 `{{message}}`——服务器往里放什么，静态扫描看不见。

## 做法：把已有那个放到唯一的出口上

HTTP 响应只能从 `PortalHttpServer#json` 出去。闸装在那里，
出口路径由 `#route` 挂在 `response` 上（Symbol 键），不靠调用方传。

于是「往公开面塞脏东西」在结构上做不到，不需要谁记得调用。
变异测试里「闸从出口上摘掉」和「出口路径不挂了」两刀都转红。

`assertPublicEgress` 在 `portal-server.js` 里只出现**一次**，有测试钉住这个数字：
散到各个处理函数里就又变回「记得调」的行为保证。

## 分两层，因为「公开」有两种

| | 完全不鉴权（`/api/join` 三条） | 鉴权后（`/me`、`/admin`） |
|---|---|---|
| 值扫描（wxid / 绝对路径 / 密钥 / 内部 ID） | ✓ | ✓ |
| 键黑名单（`text`/`content`/`body`…） | ✓ | **✗** |
| 顶层键白名单 | ✓ | ✗ |

## 差点砍下去的那一刀

第一版把键黑名单铺到了**所有**出口。那份清单里有 `text` / `content` / `body`——
而后台对话那一栏和「我的主页」的全部意义，就是把这个人自己的 `text` 显示给他看。

全出口套上去的话，那两页在线上直接变空，**而测试全绿**：
既有的后台测试确实用真 HTTP 打过 `/admin/api/conversations`，
但它的 stub 回的是空 feed，所以「闸把 text 吃掉了」它也抓不到。

抓到它的不是推理，是去读了真实响应的字段名。
现在有一条真 HTTP 测试带着真 `text` 打那条路由，断言 200 且字节里读得回来。

## 另外两个自己的 bug

**白名单是编的，不是抄的。** 第一版凭印象写了 `qr` / `expiresAt` / `hint`，
真实响应是 `ok/ready/status/ticket/qrDataUri/message/open/full`——
整条公开入口被自己的隐私闸拦下。编出来的形状让守卫看起来在工作，实际是在拦自己。

**拿长度当「原始私聊」的判据。** 超过 240 字就算没投影过。
它当场误杀了公开入口的二维码（`qrDataUri` 是一整张 SVG 的 data URI，几千字符）。
判据本身也错：`/admin` 上主人读对话、`/me` 上本人读自己的东西，长文本正是那两个
出口存在的理由。改成按出口分——不鉴权的钉死顶层键，鉴权的本来就该给本人看他自己的。

一条会把主路径拦下的守卫，最后一定会被谁「先注释掉看看」，然后再也没打开。

## fail-closed，且报错不能变成第二次泄漏

查出泄漏就**拒发**（500 + `RESPONSE_WITHHELD`），不是脱敏之后接着发。
脱敏接着发会把上游那个 bug 藏起来——那一版代码依然在往公开面塞脏东西，
只是这一层每次都在替它擦。

日志和错误对象只带 **JSON 路径**，永远不带值：
带值的话，一条「泄漏了」的日志本身就是那次泄漏，而且它落在普通日志里，
泄漏面比原来更大。

`session-event` 的两种违规分开报（`EGRESS_PRIVATE_FIELD` / `EGRESS_PRIVATE_VALUE`）：
字段名不该出现和值看起来是私密的，修法完全不同。

## 实测（真服务器、真请求）

见 `projection-scan.json`：

| 探针 | HTTP | 泄漏 |
|---|---|---|
| 干净响应（含 2KB 二维码） | 200 | false |
| 微信 ID | 500 | false |
| 绝对路径 | 500 | false |
| 内部 thread ID | 500 | false |
| 白名单外的字段 | 500 | false |
