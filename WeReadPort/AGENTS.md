# 微信读书笔记迁移：路径级开发规则

父级仓库规则继续有效；本文件只收紧当前应用。

## 不可变产品合同

- 不得提交、持久化、记录、追踪、分析或暴露真实微信读书密钥、原始笔记响应、导出笔记、压缩包或用户身份。
- P0 无 D1、无服务端用户状态；用户只在当前浏览器会话使用本人绑定的 `wrk-…` 密钥。
- 服务端代理只能调用 `src/core/constants.js` 冻结的腾讯官方接口地址、接口白名单和参数白名单。
- 每个上游请求必须携带冻结的官方技能版本；响应包含 `upgrade_info` 时立即停止受影响操作。
- 上游或业务失败不得变成空结果或看似完整的成功导出。
- 必须保持确定性导出、稳定文件名、路径安全、受保护补充区、部分失败报告和离线搜索。
- P0 只提供匿名导出；不得加入登录、账户或服务器端用户笔记库。
- 所有最终用户可见界面、错误、帮助、导出说明和运维展示默认使用简体中文；标准名、软件名和机器标识可保留英文，但必须有中文语境。

## 零等待执行

- 不得把真实时间浸泡、观察期、Alpha/Beta/GA 等待、重复审批、人工签字、非必要集成或广覆盖测试设为部署前置条件。
- 核心确定性验证通过后立即部署匿名核心到 Sites 默认生产网址；广浏览器、负载、混沌、恢复和时间型验证应实现为可立即手工触发的 CI 或 systemd 自动任务，并在上线后继续积累证据。
- 只能因已证实的密钥/隐私泄漏、跨用户访问、缺少生产写权限、真实资源耗尽、不可逆数据损失、明确法律/平台禁止或经常性成本越界而暂停最小受影响范围。
- 普通构建错误、依赖问题、测试失败、合并冲突和可逆工程选择必须由开发 Agent 自主修复。
- Scope、Acceptance、测试集和 Definition of Done 已冻结；每个最大阶段最多 2 轮整改和 1 套最终自动盲测，同类问题必须合并。封包前复审已完成，开发 Agent 不得再次调用或委托 Verifier、Teleiosis、Persona、SubAgent、第二模型或人工 Reviewer。
