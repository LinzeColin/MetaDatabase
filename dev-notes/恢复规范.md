# 项目恢复规范（Simplification Spec）

适用于 `dev-notes/项目恢复总表-20260926.md` 列出的每个恢复项目。治理框架本体以 `LinzeColin/Governance` 双平面标准为准，本文件只规定恢复时怎么做减法。

## 1. 完成的定义

项目的**原始目的**端到端跑通，并且有一条**业务结果判据**能证明它：邮件进了收件箱、页面有当日数据、同步产出了新记录。workflow 绿、测试绿、健康检查 200 都只是前提，不是完成。

## 2. 保留什么

- 产品代码（`src/` / `app/` 等）与验证**行为**的测试。
- 双平面：`machine/facts/*.json` + 渲染出的 `文档/` 七文件 + `machine/tools/`（dual-plane CI 要求）。
- `README.md`：做什么、怎么跑、数据在哪（三段）。
- 一条专属 CI：Linux 上跑该项目全量测试。

## 3. 删除什么

- 历史证据、验收收据、run manifest、TaskPack、RUN_CONTRACT、阶段报告等**过程产物**。
- 只校验文档/流程/哈希、不校验产品行为的"合同测试"。
- 无调用方的脚本与治理诊断器。
- 已完成使命的迁移兼容层。

简化前的完整状态是 main 提交 `ee80b41ff`（2026-09-26）。取回任何被删文件：`git show ee80b41ff:<路径>`。git 历史就是归档，不另建副本。

## 4. 代码规则

- 路径一律走环境变量或相对项目根，禁止 `/Users/...`、`~/Downloads`、macOS 专属字体/命令写进测试。
- 真实数据从 `Private-Database` 经 `private_db_client.py get` 在运行时取，不进代码仓。
- 修根因，不加兜底分支；不新增抽象层，除非删掉的代码比加的多。
- 失败必须说出真实原因（错误码 + 人话），禁止只输出分类码的黑箱错误。
- 周期任务遵守 AGENTS.md 的 R2 零付费预算。

## 5. 交付

每个项目一个 PR：减法 + 修复 + 业务判据 + CI 绿。PR 描述写清删了多少文件、业务判据是什么、哪些步骤需要 Owner 在本机或线上执行。
