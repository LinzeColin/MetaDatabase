# EEI 商域宇宙：手机、深浅色、无障碍体检与修复（2026-10-01）

分支 `cloud/eei-universe-a11y-261001`。只改 `EEI/apps/universe/` 的 `index.html`、`app.js`、`styles.css`，不碰 `deploy/`、数据接口、nginx。截图在 `dev-notes/assets/eei-universe-a11y-261001/`。

## 怎么测的

- 本地起静态服务（目录就是 `EEI/apps/universe/`，开 gzip，和线上 nginx 一致），`/v1/*` 用 curl 转发到线上 `https://eei.linzezhang.com`（数据是真实线上数据，响应缓存在本地，改前/改后吃同一份数据）。不关 TLS 校验。
- Playwright Chromium 无头，软件渲染（swiftshader，没有 GPU）。视口：桌面 1440x900、手机 375x812（触屏、2x）、平板 768x1024、手机横屏 812x375（额外加测）。浅色与深色各跑一遍。
- axe-core 4.11.4（和官方执行器同一份、校验值一致）；对比度：隐藏文字后截图取文字框内背景像素，与文字实色（含透明度）算 WCAG 比值，正文 <4.5、大字 <3 判不合格；触控目标取所有可操作元素的外框；遮挡取各面板外框交叠。
- 每个视口测两个状态：「首屏」（全宇宙）和「星系」（搜 NVIDIA 飞进去并选中恒星，再按 Esc 两次）。

## 性能（同一沙箱、同一方式、改前/改后交错各 8 次取中位数）

注意：沙箱没有 GPU，WebGL 是软件渲染，帧率和长任务数字比真机差得多；这里只能用来比「改前 vs 改后」，不代表真机。体积与请求数不受影响。

| | 改前 | 改后 |
|---|---|---|
| 传输体积（gzip，含 `/v1` 数据） | 351.1 KB | 355.7 KB（+4.6 KB，+1.3%；全是新增的星表/地标/样式） |
| 其中静态文件 | 304.9 KB | 309.4 KB |
| 请求数 | 27 | 27 |
| 加载到遮罩消失 中位数（桌面 / 手机） | 2.1 s / 1.1 s | 1.3 s / 1.7 s（run 间波动 ±1 s，无稳定差异） |
| 前 8 秒主线程长任务总时长 中位数（桌面） | 2609 ms（1841–3165） | 2442 ms（1316–2856） |
| 同上（手机） | 1498 ms（1059–2163） | 1620 ms（1054–2078） |

结论：区间重叠，没有可见的性能变差。星表只在展开时才建 DOM（最多 61 个按钮）；视口偏移每帧只做一次比较，仅在面板开合或窗口变化时才改相机。

## 改了什么

1. **地标与读屏**（`index.html`）：天体标签（200+ 个 div）收进 `aria-hidden` 容器，画布、工具栏、提示、状态收进 `<main>`；品牌区是 banner；图例/星表是带名字的 region；详情卡是带名字的 complementary；`aria-live` 从整张详情卡挪到一行短说明。
2. **星表**：见上表「键盘」。窄屏上星表是底部抽屉，选中后自动收起，焦点留在星表按钮。
3. **对比度**：`--ink-3` `#5f7f7e` → `#8eacab`、`--ink-2` 提亮；面板底更不透明（详情卡 0.9）；天体标签加半透明深色底（原来只有黑色文字阴影，叠在发光行星上看不清）；提示条加底；图例「已隐藏」状态原来是整个按钮变淡到 38%（对比度约 3），改成删除线 + 空心色点；证据链接加下划线（原来只靠颜色区分）。
4. **触控目标**：图例、星表、搜索结果、工具栏、详情动作、关闭钮全部 ≥44px；搜索输入框撑满整条（原来可点区域只有 18px 高）。
5. **窄屏版面**：左列改成 flex 容器，品牌/星表/图例不再各自 fixed 乱叠；详情卡与星表在手机上是工具栏上方的抽屉（原来盖住工具栏）；抽屉打开时图例和品牌卡让位；手机横屏（高 ≤520px）单独一套：面板在左列，详情卡在右侧。
6. **取景避让**：窄屏上用 `camera.setViewOffset` 把星图挪进没被面板盖住的区域，并按可用区域算相机距离（窄屏 `maxDistance` 提到 4600，否则拉不够远）；面板开合时平滑让位。
7. **其它**：键盘焦点环；`prefers-contrast: more` 下面板不透明；横滚无；`prefers-reduced-motion` 原本就有，保留。

## 我亲眼看过截图后的结论

看过：改前桌面/手机/平板首屏、改前手机/横屏星系态；改后桌面首屏与星系态、手机首屏与星系态与星表、平板首屏与星系态、横屏首屏与星系态、桌面星表态。

- 改前手机/横屏星系态：详情卡半透明，星光透出来，卡片上的小字几乎看不清；横屏时详情卡横跨整屏，把标题、数字、图例全盖住。改后：卡片不透明、文字清晰，恒星在卡片上方可见。
- 改后手机首屏：副标题、三个数字、数据截至时间、恒星名都清楚；恒星名有深色底，不再糊在光晕里。
- 仍有的问题（如实写）：
  - 三维场景在自动旋转，天体画面有时会从面板底下经过（手机竖屏的「特斯拉」小标签被图例压住一半；横屏时「Tesla」靠近右下角工具栏；伯克希尔的恒星在手机左缘被截一半）。面板是半透明浮层、不是版面冲突，但视觉上不够干净，要彻底解决得改成「按可见区域重新摆布全部恒星」，超出本次范围。
  - 桌面前 14 秒的操作提示条会压在画面最下缘那颗恒星（特斯拉）的名字上，14 秒后自动消失。
  - 手机上「查看原文」链接拉到 44px 后，详情卡里每条关系的行高变大，一屏看到的关系条数变少。
  - 暗色截图（`prefers-color-scheme: dark`）与浅色完全一致，我没有逐张看暗色截图，只靠计算（页面本来就只有一套样式）。

## 没改的与没验证的

- **不做浅色主题**：星空场景靠发光叠加（additive blending）和辉光，浅色背景下天体与光弧会消失，改它等于重做视觉；用户明确强调沉浸式体验。所以「不响应 `prefers-color-scheme`」是有意保留，在 CSS 里写了原因。
- 画布本身不能用键盘旋转/缩放；键盘用户用「星表」直达天体，鼠标/触屏用户操作不变。
- **没有用真实读屏软件（VoiceOver / NVDA / TalkBack）验证**，只验证了 axe、地标结构、`role="status"` 文字更新、键盘走查（Tab→回车→Esc）。
- 没在真机、真 GPU 上测帧率。
- 没动 `/?subject=...` 平面图谱（R 任务在改）。
- 清洁室与发布清单（`EEI/` 下自动生成件）的重新生成见 PR 描述。
