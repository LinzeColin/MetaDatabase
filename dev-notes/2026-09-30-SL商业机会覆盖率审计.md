## 一句话结论

1. 「0 个通过」**主要不是数据取不到**：把这次能补的全补上后，PASS 仍是 0，最高 58.4 分（门槛 65，差 6.6）。
2. 取数确实有真漏洞（真实候选池 1232 只上实测）：现金/债务类因子 21%–37% 被记成 NO_EVIDENCE，其中一大半是旧口径读不到（标签换了、现金流被营收的截止日绑死、银行没有「营收」标签）。补完后：`durability_balance_sheet` 无证据 21.4%→4.9%，`balance_sheet_funding` 37.2%→19.9%，`issuer_exposure_attribution` 17.7%→12.7%，`financial_capture_path` 23.3%→15.1%。
3. 同时抓出一个反向漏洞：55 只公司的营收 TTM 其实是 1–13 年前的旧数（营收标签已停止披露），却被当成「当前敞口证据」算分。现在按「与最近一份 10-K/10-Q 报告期相差 >100 天就不算」处理，这些名字诚实地回到 NO_EVIDENCE。
4. 剩下的无证据基本是结构性的：`expectations_variant`（权重 12，100% 无证据）需要一致预期，免费一手数据里没有；而且**即使它拿到满分 10，全池最高也只有 64.5 分，仍过不了 65**，所以它不是卡住 PASS 的原因。

### PASS 为什么仍是 0（卡在哪一门、差多少）

- 最高分 58.43，离 65 差 6.6。卡的是分数门，不是覆盖率门（前几名基础覆盖率都是 0.88，置信度 74–78，均过 55）。
- **覆盖率不是瓶颈的证据**（对改后收据做的上界推演，纯算术，不是评分）：若把 `expectations_variant` 设成满分 10，全池最高 64.5，仍 <65；设 8 → 最高 60.2。若把其余所有无证据因子也都假设成「基础分满分 10、风险 0」，那是荒谬乐观的情形，仍只有 73 只过 65，且其中绝大多数因 E 级/置信度/必备维度过不了状态门。
- 分数被规则的结构性上限压住：敞口评分最高 6（没有分部数据，见表）、催化剂最高 6（没有已确认日期）、研究优势最高 8、同业表最高 8，观察到的 88% 权重下基础分理论上限约 78（按代码里各表最高档粗估），实际最高 66.7；再减风险扣分（前几名 3–7 分）与不确定性扣分（0.15×(100−置信度)≈3.7）。想过 65，基础分要 ≥~71。这是 Owner 的 Skill 评分表在「免费一手数据、无分部、无一致预期」下的真实口径，**不靠改门槛或评分表让 PASS 出现**。
- 结论：现在商业机会分支对全池没有值得推到 DILIGENCE_NEXT 的公司，是公司不够好 + 规则结构性上限，而不是因子取不到。

具体口径规则（都写在代码与测试里）：

1. 银行营收 = `InterestIncomeExpenseNet + NoninterestIncome`（另认 `RevenuesNetOfInterestExpense`），放在营收概念序列最后，有标准营收标签的公司不受影响。收据里的证据标签会写出这个组合，链接指向该期申报原文。
2. 营收 TTM 截止日比该公司最近一份 10-K/10-Q 的报告期早 >100 天 → 视为营收已停更，营收类全部记 NO_EVIDENCE，并在 `notes` 写 `REVENUE_TTM_STALE:...`。100 天 = 允许最多落后一个季度。
3. 经营现金流 TTM 独立取数，新鲜度同样 ≤100 天；经营现金流率、自由现金流仍要求与营收同一截止日。
4. 债务：总额类加 `DebtAndCapitalLeaseObligations`、`DebtLongtermAndShorttermCombinedAmount`；非流动加 `LongTermDebtAndCapitalLeaseObligations`；流动加 `LongTermDebtAndCapitalLeaseObligationsCurrent`（含融资租赁，是财报上的债务行）。

## 没做的 / 坑 / 风险

- **完整 `signal-lattice research` 没在沙箱跑**（原因见上）；其它四个分支在改后数据上没验证输出（它们的代码与默认口径都没变）。服务器上第一轮研究层会多一次全池 companyfacts 补取（约 1232 次请求，约 5 分钟，在 90 分钟超时内）。
- 没补的（口径不唯一或需要新评分规则，属于改判定规则）：分部收入（敞口归因）、`CostOfGoodsAndServiceExcludingDepreciation...` 毛利、`ConvertibleNotes/NotesPayable/LineOfCredit/ShortTermBorrowings` 等杂项债务标签（本可再覆盖约 90 只的债务，但会与总额重复计数，口径不清）、营收同比退到单季同比。
- 「债务标签存在但停在旧期间」的公司不猜零、不猜已还清，保持 NO_EVIDENCE。
- 低覆盖率名字的分数受「无证据不入分」归一化影响会虚高（见上），由覆盖率下限兜住，没改。
- 回测：`hub_backtest` 调用 `commercial_receipts`，会自动用新口径；回测报告绑定的是参数 sha256（没变），所以**现存回测报告不会因此失效，但它是用旧口径算的**。建议部署后手动刷新一次回测（`sudo systemctl start signal-lattice-v2-backtest.service`），否则规则自证门读到的是旧口径的回测。
- 基线测试：官方 CI 固定 `pytest==8.4.2 setuptools==80.9.0`；用更新的 setuptools 会使 `test_v2_wheel_install_and_rollback_console_paths_complete` 因 `install_layout` 失败，与本任务无关。

## 给主线：服务器上怎么验证（原样可执行）

部署本分支合入 main 后的 release，然后：

```bash
# 1. 部署前先留一份「改前」产物（取最新的一份 verdicts）
BEFORE=$(ls -t /var/lib/signal-lattice-v2/research/out/*/stock-commercial-opportunities/verdicts-*.json | head -1)
sudo cp "$BEFORE" /tmp/sl-commercial-before.json

# 2. 部署后手动跑一轮研究层（休市日会直接退出；首轮多一次全池 companyfacts 补取）
sudo systemctl start signal-lattice-v2-research.service --no-block
journalctl -u signal-lattice-v2-research -f          # 看到 companyfacts_concept_backfill 与 cycle 完成

# 3. 读结果：覆盖率、分数分布、PASS 数、前后对比
AFTER=$(ls -t /var/lib/signal-lattice-v2/research/out/*/stock-commercial-opportunities/verdicts-*.json | head -1)
sudo -u signal-lattice /opt/signal-lattice-v2/current/venv/bin/python -m signal_lattice.branches.commercial_audit "$AFTER" --before /tmp/sl-commercial-before.json

# 4. 刷新回测（让规则自证门读到新口径的回测）
sudo systemctl start signal-lattice-v2-backtest.service --no-block
```

怎么读：第 3 步输出里「因子 NO_EVIDENCE 占比」应与上表「改后」同量级（候选池日期不同会有小偏差）；`PASS` 行照实——0 只就是 0 只，列出的每个 PASS 都带 SEC 原文链接；「前 10 名与卡点」告诉你每个差在哪一门。旧版产物没有 `meta.factor_no_evidence`，对比列会显示「没有」，这是预期。

## 在本机复现「修改前后」的做法（沙箱里用的）

`origin/main` 与本分支各用一份源码树，指向同一份事实库与日线，分别调用 `branch_entries.fundamentals_for_entries` + `commercial_receipts`，再用 `commercial_audit` 比。事实库来自 `universe.build`（带 `--fact-store`）+ `collect_companyfacts` + 腾讯日线；运行产物不进仓库。
