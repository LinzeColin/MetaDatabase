## 四、共性根因与统一治理架构

1. **证据/合同膨胀取代产品**：多个项目文档配置数超过代码数（QBVS 5.8、ADP 3.0、LinzeDatabase 2.7、PFI 1.6）。统一规则：每个项目只保留 `README.md`（做什么 / 怎么跑 / 数据在哪）+ `HANDOFF.md`（现状 / 卡点）；历史证据打包进 GitHub Release。
2. **绿不等于在跑**：ADP 投递被跳过仍显绿，阅迁定时只跑 smoke。统一规则：每个在线项目一条「业务结果」判活（邮件送达、同步成功、页面有当日数据），不以 workflow 成功代替。
3. **写死本机路径**：PFI、FIFA、Signal-Lattice 测试写死 `/Users/linzezhang`、`~/Downloads`、Mac 字体。统一规则：路径走环境变量，CI 在 Linux 上全量跑。
4. **数据迁出后没接回**：PFI、Serenity 真实数据在 Private-Database，代码没有读取入口。统一规则：项目通过 `private_db_client.py get` 在运行时取数，不落代码仓。
5. **机器提交污染 main**：ADP 回写 225 个提交。统一规则：运行状态写 Actions summary 或 Private-Database，不写 main。
6. **CI 覆盖**：dual-plane 已覆盖 9 个项目；social-archive、JobHunt 没有专属 CI。每个保留项目一条 CI 跑全量测试。
