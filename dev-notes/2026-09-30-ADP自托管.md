# ADP 自托管（从 Cloudflare 迁到 VPS-3）——交接说明

日期：2026-09-30 · 分支 `owner/adp-selfhost-261001` · 实现者交给主线。项目主人规定：Cloudflare 不产生任何费用、不再投入人工，所以 ADP 的网页、数据库、每日任务全部落到服务器；运行时不依赖任何 AI / agent / 模型调用，也不需要主人点任何按钮。

## 0. 一句话

服务器上一个容器（Node，非 root，256m）直接加载现有的 `worker_cloud.js`，数据库换成本地 SQLite 文件；每日任务是 systemd timer 起的一次性容器，arXiv 失败带退避重试、失败留记录；代码更新靠服务器每 10 分钟去 GitHub 看 `main`。**页面、选择、讲义、FSRS 的代码一行没改、没复制**——自托管运行时只在内存里改三句「整套系统跑在 Cloudflare」的自述。

## 2. 数据库选型：SQLite

- 这套程序本来就是 SQLite 方言（D1 就是 SQLite），`schema_cloud.sql` 原样可用，一条 SQL 都不用改；换 Postgres 要改 `?1`、`INSERT OR`、`ON CONFLICT`、`ROW_NUMBER` 窗口写法、`sqlite_master` 等，而 worker 里有 100+ 条 SQL，改动面大、回归风险高，收益没有。
- 单用户、日用量个位数请求 + 几百行写入，SQLite 绰绰有余；零额外进程、零额外内存（256m 上限很紧，Postgres 常驻不划算）。
- 备份就是复制一个文件：每日任务成功后 `VACUUM INTO` 一份当日快照，留 7 天（`/var/lib/adp/backups/`）。
- 用 Node 内置 `node:sqlite`（Node ≥ 22.13 不带标志即可用），**零第三方依赖**，镜像里没有 `npm install`。代价：该模块在 Node 22 里仍标「实验性」，基底镜像因此固定在 `node:22-alpine`，升主版本前要重跑测试。
- 网页容器与每日任务容器是两个进程，同写一个文件：WAL + `busy_timeout=15s`，`batch` 用 `BEGIN IMMEDIATE` 事务（与 D1 的 batch 原子语义一致）。
- D1 兼容层（`app/d1_sqlite.mjs`）有一个必须对齐的坑：`node:sqlite` 把 JS 数字一律按 REAL 绑定，而 D1 按 INTEGER。兼容层里把整数转成 BigInt 绑定，测试覆盖（`LIMIT ?`、`typeof`、自增 id、`meta.last_row_id`）。

## 4. arXiv 重试（两层）

1. `worker_cloud.js` 里**本来就有**（2026-09-30 写的，从未部署上线）：每页最多 3 次尝试，退避 2s→4s（封顶 8s），超时/网络错/429/5xx 才重试，其余 4xx 直接放弃；用尽后带着已抓到的内容返回并记 `arxiv:<原因>:truncated`。自托管直接带上它，不需要 Cloudflare 部署。
2. **本 PR 新增任务级重试**（`run_daily.mjs`）：这一轮 `degraded` 里出现任何 `arxiv:*`（含 `arxiv:parsed0`）或整轮「失败」，就按 `ADP_RETRY_BACKOFF_SECONDS`（默认 `600,1200`：10 分钟、20 分钟）再跑，**最多 3 次尝试**。worker 当天只要有一行「正常/降级/弃权」就幂等跳过，所以重试前把上一轮那行改标成 `降级·已重试`（并给它换个唯一 run_id，避免同一分钟内 run_id 撞主键被覆盖）——行保留可查；`/system` 同日多行取最新，`/api/runhealth` 与看门狗只认 正常/降级/弃权。

不静默成功：退出码 0 = 已完成且 arXiv 有数据；1 = 运行失败；2 = 重试用尽 arXiv 仍没抓到；3 = 抓取成功但库备份失败。非 0 → systemd 判 unit 失败 → `OnFailure=adp-failure@%n.service` 往 `/var/lib/adp/logs/failures.log` 追加一行并写 journal；每次尝试与最终结论另写 `/var/lib/adp/logs/jobs.jsonl` 和 `cn_meta.selfhost_job_daily`；`/api/selfhost/status` 读得到；数据变旧时 `/healthz?strict=1` 变 503；GitHub 上原有的看门狗在「最新一次日跑 arXiv=0」时照旧变红（阈值一字没动）。

## 5. 切换步骤（主线逐条执行）

**前提**：本 PR 已合入 `main`（服务器的拉取式部署追 `main`）。D1 额度每天 00:00 UTC 重置，导出要读表，**等 2026-10-01 00:00 UTC 之后再导出**。

**A. 导出 D1（需要 Cloudflare 凭据，主线做）**

```bash
npx wrangler d1 export adp-mirror --remote --output /tmp/adp-d1-dump.sql
```

导出内容是业务数据（学习状态、复习记录），**不要提交进本仓**；按「数据落地铁律」用 `KMOS/KMDatabase/machine/tools/private_db_client.py ingest` 放进 Private-Database 留底。wrangler 导不出来时的替代（每张表一个 JSON，文件名 = 表名）：

```bash
for t in cn_sources cn_items cn_selections cn_lessons cn_reviews cn_events cn_run_log cn_meta cn_artifacts cn_item_meta cn_watchlist cn_watch_seen cn_rum; do
  npx wrangler d1 execute adp-mirror --remote --json --command "SELECT * FROM $t" > /tmp/adp-json/$t.json
done
```

**B. 服务器安装（VPS-3，root）**

```bash
git clone --depth 1 --filter=blob:none --sparse https://github.com/LinzeColin/MetaDatabase.git /tmp/mdb
git -C /tmp/mdb sparse-checkout set arxiv-daily-push/deploy
sudo bash /tmp/mdb/arxiv-daily-push/deploy/selfhost/install.sh        # 只启用拉取式部署定时器
sudo systemctl start adp-web-pull.service                             # 立刻拉一次，不等 10 分钟
sudo /usr/local/bin/adp-pull-deploy.sh status adp                     # 期望 state=up-to-date
```

此时 Traefik 上已有 `Host(adp.linzezhang.com)` 的路由，但 DNS 还没切，没有真实流量。

**C. 导入数据**

```bash
scp /tmp/adp-d1-dump.sql vps3:/root/
sudo /usr/local/bin/adp-import-d1.sh /root/adp-d1-dump.sql --dry-run   # 先演练：只校验，不写
sudo /usr/local/bin/adp-import-d1.sh /root/adp-d1-dump.sql             # 正式导入；逐表行数 + sha256 核对，不一致退出码 1 且整体回滚
# JSON 方式： adp-import-d1.sh --json-dir /root/adp-json
```

导入会拒绝覆盖非空库（退出码 3）；已有库文件先整份备份成 `adp.sqlite.pre-import-<时间>`。

**D. 启用每日任务并手动跑一次**

```bash
sudo bash /tmp/mdb/arxiv-daily-push/deploy/selfhost/install.sh --enable-jobs
sudo systemctl start adp-daily.service          # 立刻跑一次（当天已成功会幂等跳过）
journalctl -u adp-daily.service -n 40 --no-pager
```

**E. 切 DNS（主线，Cloudflare 后台）**

1. Workers → `adp-cloud` → Settings → Domains：移除自定义域名 `adp.linzezhang.com`（这会删掉 Worker 自动建的 DNS 记录）。
2. DNS：新增 `adp` 的 A 记录 → VPS-3 的 IPv4，proxied（与 EEI 同做法）。
3. 等 Traefik 用 HTTP-01 签好证书（几分钟）。
4. **同时删掉 Worker 的 3 条 cron 触发器**（Workers → `adp-cloud` → Triggers）：否则 Worker 继续每天读 D1，而 D1 读取额度是**全账户共用**的（EEI 也在用），正是这次被读光的原因。

**F. 验证**：见第 6 节。

**G. 稳定几天后（主线再做）**：删 Worker `adp-cloud`、D1 `adp-mirror`、R2 `adp-raw-artifacts`，清理仓里 Cloudflare 代码。`/var/lib/adp` 要纳入服务器的每日异地备份（`linze-offsite-backup.sh`），并把 `backups/` 里的快照定期 ingest 到 Private-Database——这两件我没有权限做。

## 6. 如何证明它真的在跑

**健康检查地址**：`https://adp.linzezhang.com/healthz`，返回固定内容 `{"status":"ok","service":"adp","commit":"<提交号>"}`（不含时间，供部署器比对）。`/version.txt` 应等于 `main` 最新提交（部署器回测时强制校验）。

**页面上必须出现的内容**

- `/`：标题含「ADP 前沿学习」；六项导航（今天 复习 前沿雷达 关注 知识库 系统）；页脚「整套系统自托管在自己的服务器上」；今日精选条目；**不再出现「Cloudflare」自述**。
- `/system`：「系统与来源」「整套系统自托管（Node + SQLite + systemd 每日定时任务）」；今天这一行形如 `arXiv N · bio N · 板块流 N · 候选 N`，**N（arXiv）必须 > 0**，结果列是 正常 或 降级（降级的说明里不应有 `arxiv:` 开头的项）。

**数据多新鲜算正常**：`https://adp.linzezhang.com/api/selfhost/status` 里 `fresh` 为 `true`——即最新一条已完成运行（正常/降级/弃权）距今 ≤ 30 小时，且那次入库的 arXiv 论文数 > 0。每日任务 20:30 UTC 开跑，无重试时几十秒内收尾；重试最坏多花约 30 分钟。`fresh=false` 时 `fresh_reason` 写明原因（`no_completed_run` / `stale:…` / `arxiv_zero`），此时 `/healthz?strict=1` 返回 503，可挂到任何外部探活。

**服务器侧**

```bash
systemctl list-timers 'adp-*' --no-pager                 # 下次什么时候跑
journalctl -u adp-daily.service --since today --no-pager # 今天的日跑
tail -n 5 /var/lib/adp/logs/jobs.jsonl                   # 每次尝试 + 最终结论
cat /var/lib/adp/logs/failures.log                       # 失败记录；日常应为空或没有今天的行
ls -l /var/lib/adp/backups/                              # 应有今天的快照
sudo /usr/local/bin/adp-pull-deploy.sh status adp        # 部署器状态
```

外部还有 GitHub 上原有的 `arXiv Daily Push Liveness`（每日 22:00 UTC，探 `adp.linzezhang.com`），DNS 切过去后它就是对新站的独立探测，红了说明「跑了但没产出」。

## 7. 回滚步骤

**整体回到 Cloudflare Worker**（注意：Worker 现在处于 D1 额度用尽状态，且没有 arXiv 重试修复；D1 额度每天 UTC 0 点重置，所以回滚后大概率能恢复只读，但它不会再被维护）：

```bash
# 1. Cloudflare 后台：Workers → adp-cloud → Domains 重新添加 adp.linzezhang.com，并删除指向 VPS-3 的 A 记录
# 2. 服务器：停掉定时器与容器（数据留着）
sudo systemctl disable --now adp-daily.timer adp-backfill.timer adp-web-pull.timer
docker stop $(docker ps -q --filter label=linze.pull.app=adp)
# 3. 自托管期间产生的学习数据要带回 D1 的话，先导出： sudo sqlite3 /var/lib/adp/adp.sqlite .dump > /root/adp-selfhost-dump.sql
```

**只回退服务器上的程序版本**：部署器只追 `main`，回退 = 在 `main` 上 revert 再等 10 分钟（或 `sudo systemctl start adp-web-pull.service`）。新版本没通过健康检查时部署器自己会保留旧版，不需要手动。

**数据回退**：

```bash
docker stop $(docker ps -q --filter label=linze.pull.app=adp)
sudo cp /var/lib/adp/backups/adp-YYYY-MM-DD.sqlite /var/lib/adp/adp.sqlite
sudo rm -f /var/lib/adp/adp.sqlite-wal /var/lib/adp/adp.sqlite-shm
sudo chown 10001:10001 /var/lib/adp/adp.sqlite
sudo systemctl start adp-web-pull.service   # 或 docker start 上面停掉的容器
```
