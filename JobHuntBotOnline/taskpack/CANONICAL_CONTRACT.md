# JobHuntBot Online v0.4.0 当前版本合同

## 1. 当前版本结果

JobHuntBot Online 必须在不破坏 v0.3 已有多用户 SaaS 的前提下，证明以下用户结果：

```text
金融或法律求职者上传多份简历
→ 系统自动聚合并每六小时更新岗位
→ 先识别经验、职级、资质、准入、执业证书、工作权利和雇主担保
→ 明显不合资格岗位被拦截或降级
→ 每个岗位自动选择最合适的简历
→ 生成可下载、可编辑、只使用真实事实的岗位定制简历
→ 用户可筛选、收藏、准备申请并记录结果
→ 刷新、重登、服务重启后仍可读回
```

## 2. 北极星不变量

| ID | 不变量 |
|---|---|
| `INV-REAL-001` | 真实用户结果优先于代码、页面、提交、容器或测试声明。 |
| `INV-ZERO-TECH-002` | 普通用户只使用中文网页，不接触命令、配置、数据库或密钥。 |
| `INV-TENANT-003` | 简历、资料、推荐、申请包、进度和导出严格按账户隔离。 |
| `INV-TRUTH-004` | 不虚构经历、数字、资质、学历、工作权利或身份事实。 |
| `INV-AI-005` | 平台统一管理人工智能服务；模型不能覆盖硬资格结论，失败不阻断基础链。 |
| `INV-REFRESH-006` | 启用岗位发现后，每轮完成后的下一轮严格安排在六小时后。 |
| `INV-PLATFORM-007` | 不绕过第三方平台限制，不托管招聘账号，不自动最终提交。 |
| `INV-RECOVERY-008` | 发布前有恢复点，迁移和部署失败可回滚，重启后结果可读回。 |
| `INV-EVIDENCE-009` | 未运行、阻断、未知和局部通过不能冒充完整通过。 |
| `INV-MAIL-010` | NitroSend 不属于依赖；邮件只使用供应商无关的标准 SMTP。 |
| `INV-CHINESE-011` | 用户界面、错误说明和人类文档默认中文。 |
| `INV-QUALIFICATION-012` | 明确不满足职级、年限、资质、准入、执业证书或工作权利时，不得显示为资格通过。 |
| `INV-RESUME-013` | 多份简历必须按岗位重新路由；默认简历只能作为分数相同时的次级因素。 |
| `INV-DOCUMENT-014` | 岗位定制文档必须可下载、可打开、原始简历不被覆盖，且内容可回到用户资料核对。 |

## 3. 语义增量

### 保留

- v0.3 的邮箱账户、多用户、租户隔离、平台人工智能、自动岗位发现、六小时刷新；
- 多来源标准化和去重、筛选、收藏、忽略、手工导入、申请包和申请进度；
- PostgreSQL、迁移、备份、恢复、回滚和第三方平台安全边界。

### 新增

- 金融、会计、投资、风险、法律、合规、合同法务等中文岗位族；
- CPA、CA、CFA、ACCA、CIMA、RG146、LLB、JD、PLT、律师准入和执业证书识别；
- 金融／法律硬资格矩阵；
- 多简历岗位级路由、选择原因和替代版本；
- 岗位定制 DOCX 下载；
- 金融／法律双用户黄金事务与全中文验收。

### 改变

- 资格判断从宽松关键词判断升级为“硬条件优先、证据逐条可见”；
- 申请包从固定使用当前默认简历，升级为按岗位比较全部简历；
- 推荐页增加领域筛选与资格证据展示。

### 删除

- 删除“所有岗位都可能资格通过”的宽松行为；
- 删除“最后上传的简历自动适用于所有岗位”的行为；
- 删除用户界面的不必要英文提示。

## 4. 当前版本范围

### 用户可见

- 邮箱注册、验证、登录、退出、重发验证、忘记密码和一次性密码重置；
- 上传、保留、设置默认和删除多份简历；
- 自动提取岗位方向、技能、经验、学历和专业资质；
- 集中确认工作权利、雇主担保、地点、工作模式、年限、资质和法律执业状态；
- 自动岗位发现、六小时刷新和来源运行状态；
- 领域、城市、岗位族、技能、来源、新鲜度、资格、相关性、机会潜力和状态筛选；
- 逐条硬资格证据、推荐理由和风险；
- 岗位级简历路由、可下载岗位定制 DOCX；
- 收藏、忽略、申请包、申请状态、证据、备注和用户数据导出；
- 管理员用户与人工智能额度管理。

### 非目标

- 招聘方发布后台或双边招聘市场；
- 未经许可抓取 SEEK、LinkedIn、Indeed；
- 绕过验证码、登录、二次验证或限流；
- 自动最终提交申请；
- 伪精确录用概率；
- 自动签署法律声明；
- 本版本收费、企业组织权限或面试结果学习模型。

## 5. 主要业务样本

### 金融样本

Early Career 金融用户具有金融分析、Excel、估值和财务建模经历；十五年经验的金融总监必须判为不符合，Graduate Financial Analyst 可通过。要求 CPA 或 CA 的会计岗位只有在用户确认相应资质时才通过，否则待确认或不符合。

### 法律样本

法律用户具有 JD、PLT、澳大利亚律师准入和有效执业证书；两年经验商业律师可通过，十二年经验总法律顾问必须判为不符合。缺少准入或执业证书时，明确要求这些条件的律师岗位不得通过。

## 6. 发布边界

GitHub 与部署会持续变化，任务包不把某个旧提交永久冻结为事实。Codex 每次重新观察当前实现，并把包内增量语义合入当前更优版本。

生产完成以当前部署上的真实功能事务为主：两类用户、两份以上简历、正确资格、正确路由、文档下载、全中文界面、全部可见控件、租户隔离、重启读回和恢复均通过。提交和部署标识只记录当次观察，不代替业务验收。

## 7. Owner Gate

只有费用增加、真实权限缺失、数据权威变化、法律／品牌风险、公开发布或不可逆操作进入 Owner Gate。普通代码、测试、接口、迁移兼容和可逆部署由 Codex自主完成。
