# JobHuntBot Online v0.4.0｜Codex 最后一公里入口

## 一句话任务

在当前 `LinzeColin/MetaDatabase` 与 `https://jobhunt.linzezhang.com` 的真实现状上，保留所有已验证功能，只合入本包新增的“金融／法律硬资格判断、岗位级多简历路由、可下载岗位定制简历和全中文体验”，完成可逆部署、真实浏览器验收、数据读回、回滚准备与落库。

## 执行顺序

1. 读取 `PURSUING_GOAL.txt`、`AGENTS.md`、`taskpack/CANONICAL_CONTRACT.md`、`taskpack/task_dag.json` 和 `taskpack/acceptance_contract.json`。
2. 重新观察最新仓库、当前运行网站、PostgreSQL、调度、后台任务、标准 SMTP、平台人工智能密钥和回滚点；GitHub 与线上会持续变化，不把旧提交当作永久事实。
3. 对比本包与当前实现，将任务分类为 `已满足／直接应用／需要适配／已有等价实现／冲突／阻断／已过时`。保护当前更好的代码，不机械覆盖。
4. 先备份，再做最小可逆适配；运行源码测试、金融／法律双用户事务、全中文界面检查、真实浏览器逐控件测试、重启读回和恢复验证。
5. 只有真实用户事务通过后才保留修改；失败回滚，不降低验收标准。

## 本包已经完成的开发

- 金融、会计、投资、风险、法律、合规、合同法务等中文岗位族识别；
- 年限、职级、专业资质、律师准入、执业证书、工作权利和雇主担保的硬资格判断；
- 明显不合资格岗位降级并展示逐条理由；
- 多份简历长期保留，按每个岗位独立选择最合适的简历；
- 选择原因、替代简历和证据分可见；
- 基于选中简历的真实内容生成岗位定制 DOCX，不覆盖原始简历；
- 金融与法律双用户、跨租户、密码重置、申请进度、重启读回的真实 Uvicorn HTTP 黄金事务；
- 推荐页领域筛选、实时筛选绑定、六小时刷新不变量；
- 用户界面与人类文档默认中文。

## 必须保留的既有能力

- 邮箱注册、验证、登录、退出、忘记密码和密码重置；
- 多账户、多用户和全部私有数据的租户隔离；
- 平台统一管理人工智能服务，普通用户不接触密钥；
- 上传简历后自动发现岗位，每六小时刷新；
- 多来源聚合、标准化、去重、来源故障隔离；
- 搜索和多维筛选、收藏、忽略、手工岗位导入；
- 申请包、申请状态、证据、备注、导出和账户删除；
- PostgreSQL、迁移、备份、恢复和代码回滚；
- 不保存第三方招聘平台密码或 Cookie，不绕过验证码，不自动最终提交申请。

## 真实验收重点

以两类高需求用户为主要样本：

- 金融用户：金融分析／会计／投资／风险岗位，核对经验、职级、CPA／CA／CFA 等资质；
- 法律用户：律师／法务／合规／合同岗位，核对 LLB／JD、PLT、澳大利亚律师准入、执业证书和年限。

必须证明：

```text
上传多份简历
→ 自动发现岗位
→ 明显不合资格岗位被拦截
→ 金融岗位选择金融简历
→ 法律岗位选择法律简历
→ 下载的岗位定制简历可打开且只包含真实事实
→ 筛选、收藏、申请包和进度可使用
→ 刷新／重登／服务重启后仍可读回
```

## 环境边界

- 当前 ChatGPT 容器中的 Chromium 被管理员策略禁止访问任何网址，因此本包没有把本地浏览器未运行写成通过；已用真实 Uvicorn、HTTP、Cookie、表单、上传、下载和数据库读回完成核心事务。
- Codex 在真实工作区必须运行 `tools/e2e_local.py` 或等价 Playwright 流程，实际点击全部可见控件并检查控制台、网络、页面错误与数据库结果。
- NitroSend 已永久移除；邮件只使用任意标准 SMTP。暂缺 SMTP 只阻断邮件验收，不得阻断其他安全工作。

## Codex 完成标准

执行 `deploy/acceptance.sh`。最终报告必须基于真实功能结果，而不是提交数、HTTP 200 或容器存活。至少包括：

- 金融与法律两类用户的正确推荐与硬资格结果；
- 岗位对应简历选择和 DOCX 下载结果；
- 全中文界面和全部可见控件的实际操作结果；
- 两账户隔离、密码重置、六小时刷新、重启读回和备份恢复；
- 当前部署入口、回滚目标和唯一未解决事项。

Owner 不运行命令、不编辑配置、不判断日志。只有真实权限、费用、法律、数据权威或不可逆操作才进入一个封闭 Owner Gate。
