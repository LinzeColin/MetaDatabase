# Run Contract — Owner 走查缺陷（2026-08-11）

> 这份不属于 S0–S6 的阶段序列，不要按 S/T 顺序去排它。
> 它记的是 **2026-08-11 在 https://mydairy.linzezhang.com 线上实测到的、Owner 自己会撞到的缺陷**。
> 独立验收结论是 **断了**：一个第一次来的人，走到第 1 步就走不下去。
> **优先级高于 S5/S6 的任何一项** —— S6 的「最终独立验收」建在一个第一步就断的产品上没有意义。

## 目标

让一个**没登录**的人打开 https://mydairy.linzezhang.com ，屏幕上不出现任何一句假话；
让一个**登录了**的人点一次「早起 打卡」，点完就看得见打上了，刷新之后还在。

一次只通这一条。这条通之前不做新功能、不做设置页、不做主题。

## 实测到的缺陷（每条都附了当天的原始观察，不要重新研究，直接修）

### D1 · 点打卡，屏幕上什么都不发生（最要紧）

- **实际**：未登录状态点首页「早起 · 点击打卡」，卡片文字仍是「点击打卡」，
  没有提示、没有报错、没有跳转。后台 `POST /api/mydairy/habits?request_id=builtin-habit-01-v1`
  返回 **401**，屏幕上一个字都没说。
- **期望**：点下去要么跳登录页，要么就地显示「要先登录才能打卡」。
- **判据**：未登录点任意一个打卡卡片，屏幕上必须出现一句人话，或发生一次跳转。
  「什么都不发生」不算通过。

### D2 · 未登录时把「读不到」显示成「没有」

- **实际**：`GET /api/mydairy/habits` 与 `GET /api/mydairy/habit-checkins` 全部返回 **401**，
  而首页显示「今日打卡 **0/5**」「今日支出 **¥0.00**」「待办未完成（空）」。
  这三个 0 是假的 —— 真相是「没登录，读不到」。
- **参照物就在同一个应用里**：`?view=diary` 已经写对了 ——
  「请先登录并完成邮箱验证，再保存和查看你的历史记录。」首页照它改。
- **顺带**：日记页同一屏还写着「还没有历史记录，新增一条吧～」，这句在未登录时也是假的，一并去掉。
- **判据**：接口返回 401/5xx 时，界面上对应的数字必须变成「未登录」或「不确定」，**不许是 0**。
  这是《LLM Agent 软件开发任务分工合同 v0.0.3》§2.3 判据二：
  **坏掉的方向必须是「不确定」，不能是「没问题」。**

### D3 · 首屏的日期、星期、时钟、问候语是构建时快照，差了 9 天

- **实际**：2026-08-11 17:08 AEST 打开，屏幕上写
  **「2026年8月2日 星期日」「11:27」「早上好，小张张～」**。
- **不是缓存**：响应头是 `cache-control: no-store`，间隔 2 秒连拉两次，返回的 HTML 里都是同一个
  `2026年8月2日 / 11:27`。这个值是打包时写进产物的。
- **期望**：日期、星期、时钟、早/中/晚问候语全部按**访问者本地时间**实时算。
- **判据**：同一个页面在两个不同时刻打开，时钟必须不同；日期必须等于访问者当天。

### D4 · `/account` 未登录时说错了原因

- **实际**：未登录访问 `/account`，页面写「请先完成邮箱验证。」+「去登录」。
- **问题**：还没登录的人会以为自己的账号出了问题，去查邮箱。
- **期望**：未登录就说「请先登录」；只有**已登录但邮箱未验证**才说「请先完成邮箱验证」。

## 只能 Owner 拍板的一件事（不要替他选，也不要因此停下 D1–D4）

《LLM Agent 软件开发任务分工合同 v0.0.3》§4 硬边界写死：

> **一个用户（Owner 自己）。不自建认证** —— 要么没有登录，要么用现成的，要么先写死一个密码。

而本项目做了：邮箱注册 ＋ 邮箱验证 ＋ Google 登录 ＋ 多租户隔离。三个选项：

- **砍掉登录**（单人用）—— 最符合合同，最快能用；
- **接 `account.linzezhang.com`**（已有的统一登录）—— 不用自己维护验证邮件；
- **先写死一个密码** —— 最省事的过渡。

**默认建议：先写死一个密码，把 D1–D4 修完，让 Owner 当晚就能打上第一个卡。**
认证方案等这条链路通了再定。**这一条没定之前，D1–D4 照做，不许拿它当 blocker。**
