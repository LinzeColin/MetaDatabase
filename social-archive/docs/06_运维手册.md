# 运维、恢复与零费用手册

## 日常命令

**先分清你在哪台机器上——两套命令不能混用。**

### 本机自建 / 开发机

```bash
bash scripts/start.sh
bash scripts/stop.sh
bash scripts/doctor.sh
bash scripts/backup.sh
bash scripts/restore.sh --dry-run <恢复点>
bash scripts/export.sh all
```

### 生产（OVH，systemd 托管）

生产的 Core 由 `social-archive.service` 管着。**不要在生产上跑 `stop.sh`**
——它执行 `docker compose down`，而 systemd 会把容器再拉起来，你会看到
一个自己反复重启的服务，并以为是故障。

```bash
systemctl status social-archive.service
systemctl restart social-archive.service
bash /opt/social-archive/scripts/check_durability_units.sh   # 保命的 unit 有没有启用
journalctl -u social-archive-replication -f                   # 复制真的在跑吗
```

### 保命的三个 timer（**装好之后必须显式启用**）

`prepare_systemd_host.sh` 按设计**不启用**任何 unit（装好 → 验收 → 显式启用）。
2026-08-04 实测：生产上 backup / replication / private-database-sync
三个 timer **一直是 disabled，journalctl 90 天内全是 No entries**，
结果是 549 个制品里 530 个一个异地副本都没有。

```bash
systemctl enable --now social-archive-backup.timer \
                       social-archive-replication.timer \
                       social-archive-private-database-sync.timer
bash /opt/social-archive/scripts/check_durability_units.sh
```

## 运行不变量

- API 与 Worker 可以重启；任务通过 SQLite Runtime Journal 恢复。
- 完成态事实必须进入 Private-Database，媒体对象必须有 R2 主副本。
- 每个对象记录 R2、OCI、GitHub Release 三个副本状态和哈希。
  **注意这是目标，不是现状**：它只有在上面三个 timer 启用之后才成立。
  当前是否成立，用 `/v1/status` 的 `storage.completion` 或
  `check_durability_units.sh` 现场核，别假定。
- `status.linzezhang.com` 只展示只读摘要，不保存权威状态。
- Runtime 不依赖开发 Agent、聊天线程、人工保活或 macOS launchd。

## 配额与降级

| 存储 | 软门 | 硬门 | 硬门动作 |
|---|---:|---:|---|
| Cloudflare R2 | 8 GiB | 9.25 GiB | 暂停新 L3；L0/L1 继续 |
| OCI | 16 GiB | 19 GiB | 暂停镜像并告警，不删除 R2 主对象 |
| GitHub Release 加密包 | 8 GiB | 9.25 GiB | 暂停新包，R2/OCI 不受影响 |
| Git 工作树 | 0.8 GiB | 1 GiB 目标 | 拒绝媒体与大对象进入 Git history |

任何接近供应商实际免费限制的值都必须由部署前探针重新读取并取更低值；任务包数值是安全预算，不是供应商合同保证。

## 恢复顺序

1. 只读验证恢复点、清单、签名/哈希和目标路径。
2. 新建空目录恢复 Private-Database 快照，不覆盖现有工作树。
3. 重建 Runtime SQLite、FTS 与 PWA Projection。
4. 按 R2 → OCI → GitHub Release 优先级恢复缺失对象。
5. 对 Fixture 运行端到端读取、关系、对象哈希和重启验证。
6. Owner 确认后才允许切换当前部署；失败时删除新目录，不改变旧部署。

## 单平台故障

Connector 连续失败达到阈值后进入 `degraded`，只停止该 Connector 的自动任务；通用当前页采集、其他平台、搜索和导出保持可用。恢复探针成功两次后才自动解除熔断。
