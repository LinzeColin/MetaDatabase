# 系统架构

## 总体结构

```text
Chrome 扩展 / 官方导出 / Social Archiver Vault / 平台 API / 隔离 Worker
                              │
                              ▼
                SourceConnector + 三门禁
                  Policy / Auth / Technical
                              │
                              ▼
                 Observation / Relation / Job
                              │
                    OVH SQLite Runtime Journal
                              │ Outbox（幂等）
             ┌────────────────┼──────────────────┐
             ▼                ▼                  ▼
Private-Database API     R2 primary-objects   搜索/PWA 投影
结构化长期事实              对象字节权威源          可重建
             │                │
             │                ├── OCI 异地镜像
             │                └── GitHub private Release 加密分片
             ▼
status.linzezhang.com 只读状态投影
```

## 架构风格

核心采用**六边形模块化单体**：一个 FastAPI 控制面、一个独立 Worker 进程、一个 Runtime SQLite。平台连接器、对象存储、长期事实仓、搜索投影和导出全部通过 Port 接口隔离。这样比微服务更适合零费用与单人运维，同时第三方 GPL/AGPL 工具仍保持容器/进程边界。

## 关键端口

- `SourceConnector`：读取列表、读取单条、生成 Observation 与关系。
- `ArtifactWorker`：下载媒体、字幕、元数据、OCR/ASR 输入。
- `MetadataRepository`：经官方 clone-free Private-Database API 将完成态事实幂等入库；不得挂载、clone 或写本地工作树。
- `ObjectStore`：R2 主对象、OCI 镜像、GitHub Release 加密包。
- `SearchProjection`：可从权威事实重建的 SQLite FTS/PWA 索引。
- `ExportSink`：Markdown、Obsidian、Notion、Bookmark、ArchiveBox、WACZ。
- `SecretBroker`：只从环境、Docker secret 或受限文件读取凭证，不向日志和事实层传播。

## 公网入口与状态投影

- Compose 的 Core 容器内端口是 `8765`，但只映射到隔离的 `127.0.0.1:18765`（`.env` 的 `SOCIAL_ARCHIVE_CORE_LOOPBACK_PORT`）。Cloudflare Tunnel 的资料库与扩展 API hostname 都转发到该 loopback 地址；默认路由返回 404；OVH 不开放 Core 公网端口，也不占用现有服务的 loopback 端口。
- `social-archive.linzezhang.com` 是资料库/UI，仅由 Cloudflare Access 放行。Core 只在精确 UI Host 且有 Access Assertion 时接受该替代身份。
- `social-archive-api.linzezhang.com` 是独立扩展 API，不发生交互式 Access 登录。只有 health、配对状态和配对交换是无 Bearer 入口；配对受 10 分钟、5 次错误、16 KiB 和每 IP 每分钟 10 次的门控。
- `status.linzezhang.com` 已有全域状态站。Social Archive 只在 `/social-archive.json` 与 `/social-archive-health` 提供投影：`social-archive-status-web.service` 绑定 `127.0.0.1:18780`，Tunnel 先精确转发这两个路径，其他既有路径仍转到本机 Traefik。它只读取脱敏、allowlist 状态摘要，只允许 `GET`/`HEAD`，不保存权威状态，也不包含 Runtime、正文、对象路径、Provider 回包或 Secret。

## 每个平台的三层路径

1. **首选路径**：官方 API/导出或成熟 Worker。
2. **兼容路径**：gallery-dl、yt-dlp、Instaloader、bilibili-cli 等隔离 CLI。
3. **永远存在的兜底路径**：Chrome `activeTab` 保存当前页面和当前可见链接；不请求 Cookie 权限。

## 高内聚低耦合规则

- 平台选择器、命令和解析器只存在于对应 Connector 包。
- 核心只理解统一 Observation、Relation、Artifact 和 ScanReceipt，不理解某个平台 DOM。
- Worker 不写长期事实，只返回标准结果；核心验证后写 Outbox。
- PWA 不直连第三方平台或对象存储密钥，只调用 Core API。
- GitHub、R2、OCI 的失败各自记录 Replica 状态，不回滚已经确认的本地事实。

## 数据一致性

- 每项内容使用平台 ID 与规范化 URL 形成稳定业务键。
- 每个对象使用 SHA-256 内容寻址；相同字节只存一次。
- Outbox 的 `event_id`、Artifact 的 SHA-256、Relation 的复合键共同实现至少一次投递下的幂等。
- `scan_receipt.completeness != complete` 时禁止生成关系删除候选。
- 完整扫描第一次缺失只记录 `missing_once`；第二次完整缺失才关闭关系。
