# Social Archive 零门槛运行手册

## 第一次使用

1. 把任务包交给开发 Agent，让它按根目录 `00_README_FIRST.md` 执行并部署到 OVH。
2. 部署后打开 Social Archive 首页。即使没有任何平台账号凭证，“保存当前页面”和 Markdown/Obsidian 导入也必须立即可用。
3. 国外平台依次启用：通用网页、Reddit、Instagram；X 官方 API 默认关闭，只有确认当前权益绝不会收费才可显式开启。
4. 国内平台运行 `bash scripts/start_workers.sh stable`，先启用小红书和快手。抖音由 DouK 健康门、gallery-dl、yt-dlp 和当前页保存共同兜底；B站使用只读 CLI。
5. 每个平台完成一次链接 Canary 后，立刻在资料库看到内容、关系和 L1/L3 状态；不用等所有平台完成。

## 每天怎么用

- 在网站选择平台并粘贴本人可访问链接，或使用 Chrome 扩展保存当前页面/当前可见卡片。
- 默认保存 L0 关系、L1 元数据/正文和 L3 媒体；L2 页面快照关闭，只有手动要求时才启用。
- 搜索、筛选、详情、导出都在同一个中文界面完成。Karakeep、Linkwarden、ArchiveBox 是可选独立阅读器，不是第二事实源。

## 文件最终放在哪里

- OVH 本地：只保留队列、运行日志和待复制对象。
- GitHub Private-Database：结构化事实、目录、对象引用和版本，不放大媒体。
- Cloudflare R2 `primary-objects/`：对象字节主副本。
- OCI：仅在 R2 已验证后写入异地副本。
- GitHub private Release：加密分片的第三恢复副本；不得把媒体直接塞进 Git 历史。

对象复制运行 `python scripts/replicate_objects.py --store all`；结构化事实同步运行 `python scripts/sync_private_database.py --once`，它只使用 `SOCIAL_ARCHIVE_PRIVATE_DB_CLIENT` 指向的官方 clone-free API client。同步成功后运行 `python scripts/backup.py --once`，将同一事实快照加密写入 R2，再镜像 OCI。上线后由 systemd timer 自动执行，缺少凭证或 client 只会显示 `BLOCKED_ENVIRONMENT`，绝不回退到本地工作树、伪装成功或产生费用。

## 出问题时

1. 先运行 `bash scripts/doctor.sh`。
2. 单个平台失败时继续使用当前页保存；不要重装整个系统。
3. Worker 停止：`bash scripts/stop_workers.sh`；重新启动稳定 Worker：`bash scripts/start_workers.sh stable`。
4. 部署回滚按 `builder/ROLLBACK.md`；任务包应用回滚使用 `.social-archive-migration/ROLLBACK_COMMAND.txt`。
5. 不输入验证码绕过工具，不上传密码，不把 Cookie/Token 提交到 Git。
