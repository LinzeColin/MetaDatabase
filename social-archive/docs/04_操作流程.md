# 操作流程与防呆

## 第一次安装

1. Build Agent 完成 Stage 0 后，Owner 只运行 `bash scripts/install.sh`。
2. 脚本检查 Docker、Git、Python、磁盘、端口、目录权限和环境文件；缺失时以中文给出唯一修复命令。
3. `bash scripts/start.sh` 启动 Core API、Worker 与 PWA；`bash scripts/doctor.sh` 输出一页中文状态。
4. 加载 Chrome 扩展后，点击“保存当前页面”；保存成功后自动打开详情页。

## 保存单条内容

1. 打开本人可访问的内容页面。
2. 点击扩展 → 选择关系类型 → “保存当前页面”。
3. Core 立即写 L0/L1，返回内容卡片；L3 进入队列。
4. 资料库表格的“归档状态”列只有三个取值，由服务端唯一决定：

   - **完整** —— 该内容至少有一个制品已 `status='complete'`。
     那个状态**只在三份副本（r2 / oci / github）全部 verified、
     且三份的密文哈希、原始哈希、加密算法都一致时**才会被置上。
   - **处理中** —— 有制品但还没走完复制。
   - **仅元数据** —— 只存了文字与链接，还没有媒体制品。

   （原文写的是卡片显示“媒体已三副本”／“文本已保存、媒体待补全”——
   那两句在 v0.0.0.6 换界面之后已经不存在。判据见
   `tests/focused/test_storage_completion_contract.py`。）

## 导入收藏列表

- Social Archiver/Obsidian：把 Vault 目录配置为 Watch Folder；新 Markdown 自动导入。
- X/Reddit：优先 OAuth/官方读取；没有授权时导入 Social Archiver 输出。
- Instagram：优先 Instaloader `:saved` 或 Social Archiver 输出。
- B站：只读执行 favorites/watch-later/history；禁止点赞、投币、关注、删除等写操作。
- 国内平台：先用成熟 Worker/CLI；若 Worker 降级，扩展扫描当前可见卡片并逐条加入队列。

## 出错时只看三处

- 首页平台卡片：哪个 Connector 降级、为什么、下一动作。
- `/health`：Core、SQLite、Outbox、对象存储和 Worker 状态。
- `bash scripts/doctor.sh --bundle`：生成脱敏诊断包，不包含 Cookie/Token/原文私密内容。

## 删除与关系关闭

- 用户手工删除本地内容前必须展示对象、副本、关系和影响范围，并要求输入内容标题确认。
- 平台列表中“没看见”绝不等于取消收藏。
- 自动关系关闭只允许：明确取消事件；或连续两次完整扫描均缺失。
- 对象垃圾回收必须先通过引用计数、保留期和三副本检查，默认只生成候选，不自动删除。
