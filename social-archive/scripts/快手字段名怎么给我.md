# 快手那条路要的东西：三个**字段名**（大约 1 分钟）

## 为什么只能你来

快手收藏列表那条请求，返回的 JSON 里「编号 / 标题 / 作者」三个字段各叫什么名字，
**只有登录状态下才看得到**。我编一份去测，测出来的绿或红都不算数
（我试过一版，7 条里 3 条丢作者，而那多半是我把字段名猜错了，不是产品的毛病）。

小红书 / 抖音 / B站 / Reddit / Instagram 这五条路都已经验通了，只剩这一条。

## 怎么给

1. 用 Chrome 打开你的**快手收藏页**（左边栏「收藏」那一页）。
2. 按 `F12`（或 `⌥⌘I`）打开开发者工具，切到 **Console**。
3. 把下面这段整个粘进去，回车：

```js
(() => {
  const seen = [];
  const origFetch = window.fetch;
  window.fetch = async (...args) => {
    const res = await origFetch(...args);
    try {
      const url = String(args[0]?.url || args[0] || "");
      const copy = res.clone();
      const text = await copy.text();
      if (text.trim().startsWith("{") || text.trim().startsWith("[")) {
        const data = JSON.parse(text);
        const walk = (node, path, depth) => {
          if (depth > 4 || !node || typeof node !== "object") return;
          if (Array.isArray(node)) {
            if (node.length >= 3 && node[0] && typeof node[0] === "object") {
              seen.push({ url: url.slice(0, 80), 数组在: path, 条数: node.length,
                          第一条的字段名: Object.keys(node[0]).slice(0, 20) });
            }
            return walk(node[0], path + "[0]", depth + 1);
          }
          for (const key of Object.keys(node)) walk(node[key], path ? path + "." + key : key, depth + 1);
        };
        walk(data, "", 0);
      }
    } catch (_) {}
    return res;
  };
  window.__ks = seen;
  console.log("装好了。往下滚几屏，再回来运行下一行。");
})();
```

4. **往下滚三四屏**（收藏列表是滚动时才去请求的）。
5. 回到 Console，运行这一行，然后把结果发我：

```js
copy(JSON.stringify(window.__ks, null, 2))
```

（`copy(...)` 会把内容放进剪贴板，直接粘给我就行。）

## 它会打印什么、不会打印什么

**只打印字段名，不打印任何内容。** 那段代码里取的是 `Object.keys(...)`——
也就是「这条记录有哪些字段」，不碰字段的值。所以发给我的东西长这样：

```json
[
  { "url": "https://www.kuaishou.com/graphql", "数组在": "data.xxx.feeds",
    "条数": 20, "第一条的字段名": ["photoId", "caption", "userName", "timestamp", ...] }
]
```

**你的视频标题、作者、链接一个都不会出现。** 你也可以先自己看一眼再决定发不发。

## 发完之后会发生什么

我把那三个名字接进 `list-shape.js` 的字段表（那张表的规矩是「按真实平台的字段名列，
不是我编的同义词」），然后跑一次和小红书/抖音同样的演练：
连接 → 认出收藏列表 → 条目入库 → 国内 Cookie 没离开浏览器。
跑通之后《使用说明》里快手那一行的「而我证明不了它读得回东西」就可以删掉。

## 不想弄也没关系

快手那条路现在是**记录在案的缺口**，不是假装能用的功能：
说明书里那一行写着「点下去可能失败；失败会说原因，不会假装成功」。
你不给这个，产品不会因此变坏——只是那一条一直停在「没验过」。

## 别再走这条路：公开页面推不出收藏响应的字段名（2026-08-12 试过）

想把这件事从 Owner 手上拿掉，试了不用登录态去推字段名，**结论是推不出来**：

    https://www.kuaishou.com/short-video/…   → 63 字节，只有一句重定向
    https://live.kuaishou.com/               → 104 KB，键是 camelCase（cityName / shortName），
                                               作者相关的是 "author" / "user"——两个都已经在 AUTHOR_KEYS 里
    https://v.kuaishou.com/                  → 322 KB，**出现了 "userName"**

差一点就据此把 `userName` 加进 `AUTHOR_KEYS`。读了那处上下文才发现它不是数据字段：

    user_id: ie("userId") || ie("ud") || ie("userName")   // radarSDK 里读 cookie

**那是个 cookie 名，不是收藏条目里的作者键。** 按它改产品，等于拿遥测 SDK 的
cookie 名去改形状识别——和「拿我自己编的夹具去改生产代码」是同一种错，
只是伪装得更像证据。

所以这一格仍然是：**要一份真实的快手收藏响应的字段名**，而那只能来自
Owner 的登录态（或者他直接说不做）。下一个人别再花时间试公开页面这条路。
