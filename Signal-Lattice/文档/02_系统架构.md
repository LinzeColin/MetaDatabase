# 02｜系统架构

```text
研究层  systemd timer：美东工作日 12:00 与 16:40（休市日程序自判退出）→ signal-lattice research
  SEC 免 key（≤4 次/秒，UA 来自服务器 env）→ 候选池 → 事实库/事件库（按申报日入账）→ 不可变证据快照
  → 5 个分支各自独立子进程 → 收据 PASS/ABSTAIN/FAILED → shortlist（≤60）+ 中枢输入
  落盘 /var/lib/signal-lattice-v2/research/{work,out}；结束时原文缓存按 LRU 压到 1 GiB
回测    每月 3 日美东 18:00 → signal-lattice backtest → /var/lib/signal-lattice-v2/backtest/hub-backtest.json
实时层  systemd timer 60 秒 → signal-lattice once
  读最新快照 + shortlist 与 IWM 行情（新浪/腾讯）→ 时效门（交易时段秒数，午休/收市不计）
  → 中枢 hub（证据根去重、正反冲突、硬门、规则自证门）→ 唯一建议 / NO_ACTION / SYSTEM_BLOCKED
  → 记分簿 ledger.sqlite（只追加）→ latest.json
signal-lattice serve（127.0.0.1:8787）→ web/ 每 30 秒轮询 /api/v1/report/latest
Cloudflare 隧道 → https://signal-lattice.linzezhang.com
```

关键文件：`research_cycle.py`（研究层管线）、`branches/`（5 个分支）、`hub.py`（中枢与自证门）、`ledger.py`（记分簿）、`research_view.py`（实时层读研究产物）、`universe.py`、`evidence/`（SEC 采集）、`cache_cap.py`（缓存上限）、`nyse_calendar.py`。

研究层失败不会让实时层读旧结论冒充新结论：研究快照过期或候选池缩水（< 600 只或不足近 5 次中位数的 70%）时实时层标 `SYSTEM_BLOCKED`。运行时零第三方依赖（仅标准库）。安装：`scripts/build_wheel.py` → `scripts/install_release.sh`（不可变 release 目录 + current/previous 软链）；回滚 `scripts/rollback.sh`。
