# 04｜操作流程

## 研究

1. 用户提交标的、市场和期限；
2. 请求通过幂等检查进入 SQLite Queue；
3. Worker 读取服务器侧 Seal、数据和风险门；
4. 研究 Skill 生成 Claim 和 Evidence；
5. 共识层去重同源证据并保留冲突；
6. 量化层验证时间、费用、样本外、过拟合、流动性和容量；
7. 输出 Action Packet 或 `NO_ACTION`。

## Build Agent 最后一公里

Status Preflight → 核验任务包 Seal 与 Manifest → 获取最新 integration base 并做 Semantic Delta → 原样落库 → 绑定真实凭证与目标环境 → 构建与安装 → 即时故障注入 → 备份恢复回滚 → 生成业务线证据 → Status Closure → 有真实新事实才提交与备份。

不得重新研究产品、修改版本号、扩展 Scope/Acceptance、启用模型或自动交易。
