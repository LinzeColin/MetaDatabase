# 06｜运维手册

## 1. 看线上（任意电脑）

```bash
curl -s https://signal-lattice.linzezhang.com/health/live
curl -s -o /dev/null -w '%{http_code}\n' https://signal-lattice.linzezhang.com/health/ready
```

## 2. 业务判据

```bash
curl -fsS https://signal-lattice.linzezhang.com/api/v1/report/latest | python3 -c '
import json,sys
r=json.load(sys.stdin);d=r.get("decision") or {}
print(r["state"],d.get("action_code"),d.get("primary_symbol"),r.get("generated_at"))'
```

`state=DATA_READY` 且 `decision.action_code` 是 `RECOMMENDATION` 或 `NO_ACTION` 为正常；`SYSTEM_BLOCKED` 先看研究层（第 5 节）。

## 3. 生产机 VPS-3（`ssh linze-vps3`，可 `sudo -n`）

```bash
systemctl list-units 'signal-lattice*' --no-pager
systemctl list-timers 'signal-lattice*' --no-pager       # 研究层美东 12:00 / 16:40、回测每月 3 日、实时层 60 秒
readlink -f /opt/signal-lattice-v2/current /opt/signal-lattice-v2/previous
journalctl -u signal-lattice-v2-loop -n 50 --no-pager     # 只在结论变化时有一行 OUTCOME_CHANGED
journalctl -u signal-lattice-v2-research -n 100 --no-pager
```

每分钟是否在产出，看 `latest.json` 的 `generated_at`，不看 journal 有没有输出。研究层单元失败会在 journal 写一条 `signal-lattice-research` 错误行（`OnFailure`）。

## 4. 数据目录与 SEC User-Agent

- `/var/lib/signal-lattice-v2/`：`latest.json`、`ledger.sqlite`（记分簿）、`backtest/hub-backtest.json`；`research/work/`（事实库 facts.sqlite、事件库、行情 bars、证据快照 snapshots、缓存）；`research/out/<as_of>/`（分支收据、shortlist、`latest.json`）。
- SEC 要求声明联系方式：`/etc/signal-lattice-v2/research.env`（root:root 0600）写一行 `SIGNAL_LATTICE_SEC_UA=项目名 联系邮箱`。值只放这个文件，不进仓库、不进日志；缺失时研究层报错退出、不发请求。
- 缓存上限：SEC 响应缓存 + 正文缓存合计 ≤ 1 GiB（`--cache-max-bytes`），研究层结束时按最近使用淘汰；抽取结果（structure-cache 小 JSON）、事实库、快照不在淘汰范围。看占用：`sudo du -sh /var/lib/signal-lattice-v2/research/work/*`。

## 5. 研究层与回测

```bash
sudo systemctl start signal-lattice-v2-research.service --no-block   # 手动跑一次（休市日会直接退出）
sudo systemctl status signal-lattice-v2-research.service --no-pager
sudo systemctl start signal-lattice-v2-backtest.service --no-block    # 回测报告 35 天过期，每月自动刷新
```

研究层单次上限 90 分钟、内存 2G、CPU 150%。首次全量预取 SEC 数据最久（预计约 2 小时，超过单元 90 分钟上限就用第 6 节的 systemd-run 首跑，已入库的数据断点续取）；之后只取增量。研究层失败时实时层标 `SYSTEM_BLOCKED`，先看 journal，不要改门槛让它变绿。

## 6. 部署（两段式）与回滚

```bash
rm -rf /tmp/md && git clone --depth 1 https://github.com/LinzeColin/MetaDatabase.git /tmp/md
# 第一段：装 release 与单元，不切 current、不动在跑的服务
sudo env SIGNAL_LATTICE_STAGE_ONLY=1 bash /tmp/md/Signal-Lattice/scripts/deploy_v2.sh
# 在新 release 上先跑一次研究层（systemd-run，不占 ssh 会话，首跑约 2 小时；VERSION 换成新版本号）
VERSION=0.0.0.4.1
sudo systemd-run --unit=sl-research-first --uid=signal-lattice --gid=signal-lattice --property=EnvironmentFile=/etc/signal-lattice-v2/runtime.env --property=EnvironmentFile=/etc/signal-lattice-v2/research.env --property=MemoryMax=2G --property=CPUQuota=150% --property=RuntimeMaxSec=10800 --property=ReadWritePaths=/var/lib/signal-lattice-v2 /opt/signal-lattice-v2/releases/$VERSION/venv/bin/signal-lattice research --work-dir /var/lib/signal-lattice-v2/research/work --out-dir /var/lib/signal-lattice-v2/research/out --cache-max-bytes 1073741824
journalctl -u sl-research-first -f
# 第二段：研究层成功后，同一份代码再跑一遍 = 切 current 并启动全部 timer
sudo bash /tmp/md/Signal-Lattice/scripts/deploy_v2.sh
curl -s https://signal-lattice.linzezhang.com/health/live
```

回滚（切回 previous，重启 api、立即跑一轮实时层）：`sudo bash /tmp/md/Signal-Lattice/scripts/rollback.sh`；指定版本：`sudo bash /tmp/md/Signal-Lattice/scripts/rollback.sh /opt/signal-lattice-v2/releases/0.0.0.3.5`。研究层 timer 在回滚后可保留（旧版不读研究产物），也可 `sudo systemctl disable --now signal-lattice-v2-research.timer signal-lattice-v2-backtest.timer`。
