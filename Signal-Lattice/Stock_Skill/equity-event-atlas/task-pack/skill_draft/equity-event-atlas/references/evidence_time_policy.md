# 证据与时间政策

## 1. 证据等级

| 等级 | 来源 | 可否单独支撑 FACT |
|---|---|---|
| T0 | 监管机构、交易所、指数公司、发行人正式披露 | 可以 |
| T1 | 锁定版本的可信结构化解析器或数据库 | 可辅助，关键条款回到 T0 |
| T2 | 市场数据与公司行动供应商 | 可支撑行情与结构化字段，需说明许可和时点 |
| T3 | 专业财经媒体 | 可辅助解释，关键法律条款回到 T0 |
| T4 | 社交、论坛、匿名消息 | 不可以，只能触发调查 |

## 2. 声明级溯源

每个 `FACT` 至少绑定一个 `evidence_id`。证据必须保存：

```text
title
source_type
tier
url 或 locator
published_at
observed_at
sha256
```

同一来源包含多个主张时，宿主还应保存页码、段落、表格或 JSON Pointer 等最小定位。

## 3. 三个时间与分析时点

- `published_at`：来源公开时间。
- `observed_at`：系统真实看到来源的时间。
- `effective_at`：事件发生或生效时间。
- `as_of`：本次分析允许使用信息的截止时点。

Point-in-Time 硬门：

```text
observed_at <= as_of
```

不满足即 `POINT_IN_TIME_LEAK`。不得用后来看到的修订文件重写此前预测。

## 4. 冲突处理

1. 保留双方来源，不静默覆盖。
2. 区分“旧版本被正式修订”和“两个当前来源冲突”。
3. T0 与低等级来源冲突时优先 T0，但保留冲突记录。
4. 两个 T0 冲突时，事件为 `DISPUTED`，动作门阻断。
5. 无法定位原文时使用 `UNKNOWN`，不复述为事实。

## 5. 数据新鲜度

新鲜度不是固定小时数；由事件类型决定：

- 临近财报、解禁、指数调整或监管决定：宿主应在当前调用重新抓取。
- 历史完成事件：可使用已哈希快照，但需确认没有修订。
- 行情与流动性：必须与分析时点和交易日历一致。
- 供应商故障：使用缓存时明确缓存时点，并降低运行能力。
