# 宿主集成与数据治理

## 1. 组件边界

本 Skill 是纯功能组件：

```text
宿主数据适配器
    ↓
request + evidence + point-in-time market data
    ↓
LLM 或规则生成 analysis_bundle
    ↓
本 Skill 确定性校验与渲染
    ↓
宿主 UI / 报告 / 状态 / 长期事实层
```

## 2. 宿主调用顺序

1. 读取 `SKILL.md` 和本次需要的参考文件。
2. 生成请求并运行 `validate-request`。
3. 获取官方披露、交易日历、行情和用户约束。
4. 计算并保存市场能力。
5. 生成分析包。
6. 运行 `validate-bundle`；失败则只返回错误码和最小修复。
7. 运行 `render`。
8. 宿主按自身策略持久化结构化完成态与对象引用。
9. 将 `STATUS_FRAGMENT.json` 汇入既有状态系统。

## 3. 用户指定基础设施的适配原则

当接入用户现有云端系统时：

- GitHub 私有权威数据层保存结构化完成事实、版本、对象引用、哈希和恢复结论。
- OVH 上的 SQLite 只承担可重建队列、幂等、游标、Runtime Journal 与 Outbox。
- 大文件、图表、快照和含隐私对象进入 R2；结构化事实只保存引用和哈希。
- D1 仅在确有查询价值时作为可重建冷索引。
- OCI 只承担用户既定冷备策略。
- 本 Skill 不创建新的平行权威数据库。

这些是宿主集成约束，不意味着 Skill 自身部署服务或直接拥有上述资源。

## 4. 幂等与重放

推荐幂等键：

```text
skill_version + security_identity + as_of + evidence_set_hash + request_hash
```

相同键重复运行应复用或验证同一结果。证据集变化时产生新版本，不覆盖旧预测。

## 5. 状态与健康

本 Skill 无进程健康状态。宿主可报告：

- 最近成功调用时间；
- 版本与制品哈希；
- 本次市场能力；
- 四项运行门；
- 最近失败错误码；
- 是否存在待结算预测。

禁止用“进程在线”冒充数据新鲜或分析正确。

## 6. 备份与恢复

- 代码恢复：回滚目标仓库提交。
- 分析事实恢复：由宿主权威数据层按 hash 恢复。
- 图表恢复：从冻结分析包重新渲染，不需要单独成为权威源。
- 缓存丢失：从完成态事实和证据引用重建。
